## 悬停锁住原因

原实现把 Canvas 弹幕换成 DOM 菜单时，没有统一字号、内边距和行高；原生 CSS 的悬停高度及负 margin 还会改变命中范围。鼠标可能没有真正进入新节点，无法产生预期的 mouseleave。

freezeId 同时代表普通悬停与举报/登录弹窗冻结。一次性离开监听看到 freezeId 就跳过解锁，后续移动又被 hovered 的提前返回忽略，造成锁住。

修复后统一 Canvas 与 DOM 字号，设置稳定的最小命中尺寸，布局完成及播放器 pointermove 都补充边界核验。退出时同步通知原站清理所选引用，并防止 restartComment 重入；显式弹窗冻结独立保留。

## 验证边界

自动化用真实浏览器和本地媒体/账号夹具，验证渲染与交互契约，不代表登录账号上的全部服务器操作已经实测。图片 emoji 支持静态绘制，动图的持续逐帧动画未实现。字形与心形不保证和 CSS/SVG 逐像素一致。暂停发送会立即入队/调度，但滚动弹幕可能仍在右边界等待播放后进入画面，不能把“已创建节点”等同于“暂停画面内已完整显示”；该行为仍需登录态原站对照。极端密度会排队延迟，不静默截断条数。原站换模块或播放器版本时仍需检查诊断确认接管。
