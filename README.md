# 抖音网页版弹幕性能优化

针对抖音网页版在弹幕较多时播放卡顿、拖动进度条跳转后长时间无响应的问题，研究并实现本地浏览器侧的性能优化。

现已实现油猴脚本，用缓存位图和浏览器合成动画替换原弹幕引擎，保留原站设置及悬停菜单。当前版本 0.3.3。本地兼容性回归已通过；具体提速比例仍需真实视频的同条件性能对照。

## 安装与更新

将本目录 `douyin-danmaku-performance.user.js` 安装到 Tampermonkey，保存后刷新抖音页面。脚本在 document-start 接管原引擎，仅切换视频不能替代安装后的刷新。关闭优化时，在油猴中禁用脚本并刷新。

沿用原播放器的透明度、字号、速度、弹幕区域和开关。完整缺项核对及验证边界见 [功能兼容记录](docs/compatibility.md)，性能分析依据见 [调查记录](docs/investigation.md)。

## 本次修复

- 0.3.3：跳转时分批准备隐藏位图，完成后统一显示目标画面，避免逐条冒出；位图上传计入协作预算，使用可取消的消息任务接续，并补齐准备期间经过的时间段。暂停和异步回包仍能完成恢复，不丢掉尚未准备的内容。
- 修复倍速播放时反复硬校正动画时间导致的前后跳动，按同一时钟建立动画起点，正常播放交由浏览器连续推进。重复速度设置不重启动画，悬停按实际显示位置命中。
- 0.3.2：跳转后回溯目标时间附近仍有效的弹幕，按原始时间计算位置，直接恢复屏幕分布，支持暂停跳转与异步数据回填。原站跳转过程的清缓存保留当前视频已加载数据，切视频/销毁时仍释放。
- 重建沿用 4ms 协作预算；先测量、分轨，再为可显示弹幕生成位图，避免对排队内容反复绘图。已过期历史不补播，目标附近没有下载的数据仍需等待原站返回。
- 0.3.1：调度改为独立定时任务，空闲时降低唤醒频率，新数据立即唤醒；复用等待弹幕的测量结果，集中数据按时间预算分批处理，不截断弹幕数量。
- 修复播放器缩放后悬停错位、字号/宽度变化后的重叠、底部固定弹幕轨道碰撞、服务器提前回包造成的重复弹幕，以及分批处理时新数据覆盖读取位置的问题。
- 倍速状态下重建动画保留实际速度，暂停及冻结时减少无效动画时间写入。
- 0.3.0：弹幕移动改用 Web Animations transform 动画，普通播放不再每帧清空和重画整屏 Canvas。文字与表情仍缓存为 Canvas 位图，仅内容变化时上传。
- 修复单条弹幕变速后的追尾、图片失败后回退文字被压缩、屏幕像素密度变化以及长任务被误判为跳转。
- 抖音 emoji 图片、透明度、本人弹幕边框、已点赞标记及高赞数量。
- 改字号、速度、倍速或播放器尺寸时保留当前弹幕；单行/两行切回百分比时清除残留行数。
- 暂停发送、优先弹幕、删除待显示弹幕、更新临时 ID 后去重。
- 悬停前后保持字号和命中尺寸；鼠标在播放器内离开文字/按钮区域即可恢复，不再锁住。举报/登录弹窗的显式冻结独立处理。
- 缓冲恢复、跳转清理旧队列、销毁资源及覆盖层不拦截视频点击。

## 问题描述

- 观看弹幕较多的视频时，页面或播放器出现明显卡顿。
- 拖动进度条跳转播放时间时，可能卡住很久才能恢复播放和交互。
- 希望改善高弹幕密度下的观看体验，重点缩短跳转后的等待时间。

## 预期目标

- 降低弹幕较多时对正常播放和页面交互的影响。
- 提升进度条拖动、前后跳转以及连续跳转的响应速度。
- 保留弹幕内容，不以关闭弹幕或固定数量截断作为优化手段。
- 保持暂停、继续播放、音量、倍速、全屏和切换视频等基础操作正常。
- 优化可关闭，关闭后可恢复网页原有行为。

## 范围与实现形式

首期聚焦桌面浏览器中的抖音网页版视频播放与进度跳转。移动端客户端、直播间和视频下载不在首期范围内。

实现形式为油猴脚本。复用 `danmaku@2.0.9` 的轨道分配，以 Canvas 缓存文字/表情 sprite，通过浏览器原生 transform 动画移动。每条可见弹幕只有一个位图节点，只有悬停弹幕创建原生 React 子树。调度约每 32ms 检查新弹幕，移动不受这一调度频率限制。过密弹幕排队等待轨道，因此可能延迟显示；跳转会清掉旧时间的队列。

## 待调研事项

1. 记录可稳定复现的视频场景、弹幕密度、浏览器版本、硬件环境和其他扩展情况。
2. 在相同视频与播放区间，对比弹幕开启和关闭时的正常播放及跳转表现。
3. 采集性能记录，定位主线程长任务、弹幕数据处理、布局绘制或其他耗时环节；同时区分网络缓冲和视频解码造成的等待。
4. 确认跳转时是否存在历史弹幕集中处理、重复计算或过期任务堆积。这些仅为待验证假设。
5. 评估浏览器侧可介入的位置、对页面原有功能的影响及网页更新后的维护成本。
6. 根据瓶颈确定最小可行方案，并建立优化前后的对照数据。

## 验收方式

在同一设备、浏览器、视频、清晰度及相近网络条件下，对比原始页面与启用优化后的表现；每种场景重复测量，记录中位数和最差值。

| 场景 | 观察内容 | 预期结果 |
| --- | --- | --- |
| 高密度弹幕下持续播放 | 画面流畅度、掉帧、主线程长任务及操作响应 | 卡顿明显减轻，交互保持可用 |
| 单次向前或向后跳转 | 松开进度条到目标时间画面开始推进的耗时、界面响应 | 等待时间明显缩短，无持续假死 |
| 连续多次跳转 | 最终播放位置、响应耗时及弹幕时间同步 | 能及时响应最终跳转，不集中补播过期弹幕 |
| 低密度或关闭弹幕 | 播放与操作响应 | 不产生明显性能回退 |
| 暂停、倍速、全屏及切换视频 | 播放器基础功能与资源占用 | 功能正常，无明显累积退化 |
| 关闭优化 | 页面原有播放与弹幕行为 | 可恢复正常使用 |

具体量化阈值在取得基线数据后补充，当前不预设未经验证的提升比例或耗时承诺。

## 文件与使用

- `src/`：时间轴、表情绘制、引擎及模块接管代码。
- `douyin-danmaku-performance.user.js`：可安装的独立脚本，已包含依赖和上游许可。
- `tests/`：单元测试和浏览器兼容性回归代码。
- `docs/`：功能对照及调查记录。
- `.materials/`、`output/`、日志、截图、依赖目录：仅本地保留，忽略提交。

开发命令：

```bash
npm ci
npm run build
npm test
```

浏览器测试默认使用本机 Chrome，在后台复用一个浏览器，结束后自动关闭。可通过 `PLAYWRIGHT_CHANNEL=msedge npm test` 使用本机 Edge。

`node tools/serve.mjs` 启动本地验证页 `http://127.0.0.1:8765/`；`?engine=original` 在存在本地材料时可加载原引擎。测试页的模拟时钟不代表真实视频解码性能。

控制台可调用 `window.__DY_DANMAKU_CANVAS__.status()` 查看接管次数、回退次数、活跃及排队弹幕数、emoji 加载数和帧耗时。未识别到原模块时不接管，构造失败则回退原引擎。

## 注意事项

性能记录、截图和复现材料需去除账号信息、Cookie、token 等敏感内容。后续如保存本地采样数据或生成物，应先配置项目自己的忽略规则，避免误提交。
