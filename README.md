# 抖音网页版弹幕性能优化

针对抖音网页版在弹幕较多时播放卡顿、拖动进度条跳转后长时间无响应的问题，研究并实现本地浏览器侧的性能优化。

目前仅初始化项目文档，尚未进行性能分析或编写实现代码。弹幕与卡顿之间的具体因果关系需要通过后续测量确认。

## 问题描述

- 观看弹幕较多的视频时，页面或播放器出现明显卡顿。
- 拖动进度条跳转播放时间时，可能卡住很久才能恢复播放和交互。
- 希望改善高弹幕密度下的观看体验，重点缩短跳转后的等待时间。

## 预期目标

- 降低弹幕较多时对正常播放和页面交互的影响。
- 提升进度条拖动、前后跳转以及连续跳转的响应速度。
- 尽量保留弹幕观看体验；如需限制数量或简化显示，应允许用户选择。
- 保持暂停、继续播放、音量、倍速、全屏和切换视频等基础操作正常。
- 优化可关闭，关闭后可恢复网页原有行为。

## 范围与实现形式

首期聚焦桌面浏览器中的抖音网页版视频播放与进度跳转。移动端客户端、直播间和视频下载不在首期范围内。

实现形式待调研后确定，可评估油猴脚本或浏览器扩展。是否需要限制弹幕密度、调整调度或优化跳转时的处理流程，均以性能分析结果为依据。

## 待调研事项

1. 记录可稳定复现的视频场景、弹幕密度、浏览器版本、硬件环境和其他扩展情况。
2. 在相同视频与播放区间，对比弹幕开启和关闭时的正常播放及跳转表现。
3. 采集性能记录，定位主线程长任务、弹幕数据处理、布局绘制或其他耗时环节；同时区分网络缓冲和视频解码造成的等待。
4. 确认跳转时是否存在历史弹幕集中处理、重复计算或过期任务堆积。这些仅为待验证假设。
5. 评估浏览器侧可介入的位置、对页面原有功能的影响及网页更新后的维护成本。
6. 根据瓶颈确定最小可行方案，并建立优化前后的对照数据。

## 验收方式

在同一设备、浏览器、视频、清晰度及相近网络条件下，对比原始页面与启用优化后的表现；每种场景重复测量，记录中位数和最差值。

| 场景 | 观察内容 | 预期结果 |
| --- | --- | --- |
| 高密度弹幕下持续播放 | 画面流畅度、掉帧、主线程长任务及操作响应 | 卡顿明显减轻，交互保持可用 |
| 单次向前或向后跳转 | 松开进度条到目标时间画面开始推进的耗时、界面响应 | 等待时间明显缩短，无持续假死 |
| 连续多次跳转 | 最终播放位置、响应耗时及弹幕时间同步 | 能及时响应最终跳转，不集中补播过期弹幕 |
| 低密度或关闭弹幕 | 播放与操作响应 | 不产生明显性能回退 |
| 暂停、倍速、全屏及切换视频 | 播放器基础功能与资源占用 | 功能正常，无明显累积退化 |
| 关闭优化 | 页面原有播放与弹幕行为 | 可恢复正常使用 |

具体量化阈值在取得基线数据后补充，当前不预设未经验证的提升比例或耗时承诺。
